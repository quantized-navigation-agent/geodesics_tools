# Spatial Strategies, Not Actions: Vector-Quantized Geodesics as Tools for LLM-Driven Agents

Code for the anonymous submission.

An LLM-driven agent navigates a partially observable 2D grid world with moving
obstacles. Instead of asking the LLM to plan low-level moves, we

1. sample many **geodesic** (shortest, obstacle-aware) trajectories,
2. **vector-quantize** them into a small set of representative 5-step action
   sequences,
3. have an LLM write a natural-language **description** of each, turning it into
   a *tool*,
4. at decision time have the LLM **select** a tool given the current partial
   observation.

Four agent variants are included (see *Agent simulations* below): with tools,
without tools, with tools plus a deterministic code collision check, and a
no-LLM greedy planner used as a reference point.

All coordinates are `(row, column)`, 0-based, origin top-left, row increasing
downward. An action is a `(drow, dcol)` delta:
`up=(-1,0) down=(1,0) left=(0,-1) right=(0,1) wait=(0,0)`.


## Requirements

```
pip install -r requirements.txt
```

`scikit-learn-extra` is only needed for the default CLARA / PAM k-medoids
clustering in the quantization step.

The tool-description step and the LLM agent simulations call a vision LLM through
an **Ollama** `/api/generate` endpoint. Set your endpoint and model tag in
`simutils/vision_qwen.py`:

```python
MY_MODEL = "qwen3.6:35b-a3b"                       # the model tag served by your Ollama
MY_URL   = "http://OLLAMA_HOST:11434/api/generate" # your Ollama /api/generate endpoint
```

(or override `MODEL` / `MODEL_URL` at the top of each run script). The paper
uses `qwen3.6:35b-a3b` for both the offline descriptions and the online
selection.


## Offline pipeline (build the tool library)

Run from the repository root, in order:

```bash
# 1. sample geodesics and extract the quantization windows
python geodesic_dataset_generation.py
#    -> movement_geodesic_dataset/<id>.pkl , actions_full.pkl , actions_truncated.npz

# 2. quantize into K tools (+ 5 elementary one-step tools) and render one image per tool
python geodesic_quantization.py
#    -> quantized_actions.npz , filled_cluster_<name>.png

# 3. ask the LLM to describe each tool  (needs the Ollama endpoint set)
python generate_tool_description.py
#    -> tool_description.pkl                        (dict {tool name -> description})
#    -> qwen3_6_35b_a3b_list_of_tool_descriptions.txt  (human-readable, rebuilt every run)
```

Note: step 3 **loads** `tool_description.pkl` if it already exists rather than
regenerating it — delete that file to force a fresh run.

The offline artifacts are already included
(`quantized_actions.npz`, `tool_description.pkl`,
`qwen3_6_35b_a3b_list_of_tool_descriptions.txt`,
`actions_full.pkl`, `actions_truncated.npz`), so you can skip straight to the
simulations. The bulk geodesic dataset (`movement_geodesic_dataset/`) and the
per-tool images (`filled_cluster_*.png`) are regenerated by steps 1–2 and are
not bundled.


## Agent simulations

Same environment and same observation images for all four; only the decision
step differs.

| script | decision step | LLM |
|---|---|---|
| `run_agent_simulation_v2.py`         | LLM picks one tool from the library | yes |
| `run_agent_simulation_notools_v1.py` | LLM proposes the next 5 actions directly | yes |
| `run_sim_wtools_coll_detect_v1.py`   | a code check drops every tool that would hit a currently visible car, then: 0 safe → wait; 1 safe → take it (no LLM call); ≥2 safe → LLM picks among the safe ones | yes (only when ≥2 tools survive) |
| `run_sim_notools_heuristic_v1.py`    | no LLM: enumerate all `5**5` action sequences, rank by distance-to-goal, take the first that is collision-free against visible cars | no |

```bash
python run_agent_simulation_v2.py                 # with tools
python run_agent_simulation_notools_v1.py         # without tools
python run_sim_wtools_coll_detect_v1.py           # with tools + code collision check
python run_sim_notools_heuristic_v1.py            # no-LLM greedy baseline
```

Top-of-file parameters:

- `NR_RUNS` — number of episodes per invocation.
- `MODEL` / `MODEL_URL` — `None` falls back to `simutils/vision_qwen.py` (LLM scripts).
- `MAX_TURNS` — max decision turns per episode.
- `LLM_THINK` — (`run_sim_wtools_coll_detect_v1.py`) toggle the model's thinking mode.
- optional CLI arg = output folder name, e.g.
  `python run_agent_simulation_v2.py my_run_dir`.

Each `main()` call runs one episode into the output folder (defaults:
`simulation_plots_tools`, `simulation_plots_notools`,
`simulation_plots_wtools_cd`, `simulation_plots_notools_heuristic`); if that
folder already exists it is first moved aside to `<name>_<timestamp>`. At the end
of an episode the folder contains the per-turn images, `chat.txt` (full
transcript, last line `outcome: goal` / `outcome: collision`), and an empty file
named `goal` or `collision` giving the outcome. The tool scripts also write a
per-turn pickled log (`tool_execution_log.pkl` for the two tool scripts,
`turn_execution_log.pkl` for the heuristic one).

Per-turn images in each episode folder:

| file | meaning |
|---|---|
| `turn_<n>_full_view_pre_llm.png`  | full grid before the decision (not shown to the LLM) |
| `turn_<n>_obs_view_for_llm.png`   | partial observation window shown to the LLM |
| `turn_<n>_zoom_view_for_llm.png`  | agent-centred close-up, shown to the LLM alongside the observation |
| `turn_<n>_full_view_post_llm.png` | full grid after executing the turn (not shown to the LLM) |

To turn a pickled log into text, run inside that folder:

```bash
python /path/to/decode_tool_execution_log.py     # writes chat.txt
```

Per-condition success rate = number of `goal` markers / number of episode folders.


## Repository layout

```
geodesic_dataset_generation.py      offline pipeline step 1
geodesic_quantization.py            offline pipeline step 2
generate_tool_description.py        offline pipeline step 3
run_agent_simulation_v2.py          agent, LLM picks a tool
run_agent_simulation_notools_v1.py  agent, LLM plans raw actions
run_sim_wtools_coll_detect_v1.py    agent, LLM picks a tool after a code collision check
run_sim_notools_heuristic_v1.py     no-LLM greedy 1-turn planner (reference baseline)
decode_tool_execution_log.py        utility: tool_execution_log.pkl -> readable text

simutils/
  config.py          world / dataset / clustering parameters
  env.py             MovingWorldEnv (25x25 grid, cars move up 1 row/step, wraparound)
  env_utils.py       observation-window bounds, swept-collision test, result dataclasses
  geodesic.py        lexicographic shortest-path search
  dataset.py         env sampling + geodesic dataset construction
  clustering.py      trajectory clustering routines
  kmedoids_clara.py  CLARA / PAM k-medoids (default)
  tool_names.py      name a tool by its action letters (U/D/L/R/W), e.g. "RRWDD"
  collision_check.py replay a tool against the currently observed cars; report collisions
  prompts.py         environment / tool-description / decision prompt strings
  visualization.py   grid and tool-sketch rendering
  vision.py          single-image vision_query wrapper
  vision_qwen.py     Ollama /api/generate streaming vision call (requests only)
  log_stderr_stdout.py  stdout/stderr capture helper
```

Key settings (`simutils/config.py`): 25×25 grid, 25 cars, cars move up one row
per step with wraparound, 5-action turns, observation half-window `2*5`, `K=5`
quantized tools plus 5 elementary one-step tools, start at the top-left corner,
goal at the bottom-right corner, `NUM_DATASET_SAMPLES = 250` geodesics for the
offline quantization.
